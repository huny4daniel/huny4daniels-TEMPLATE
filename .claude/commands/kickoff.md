아이디어: $ARGUMENTS

docs/PROCESS.md의 역할 분담과 협업 규칙을 따른다.

1. **0단계 점검**
   - README.md, AGENTS.md, docs/STATUS.md를 읽는다.
   - 프로젝트 이름 자리표시자(`{{PROJECT_NAME}}`, `{{제품 이름}}`)가 남아 있으면 이름을 물어 채운다. 스택 관련 자리표시자는 2단계까지 그대로 둔다.
   - git 원격 연결 여부를 확인하고, 없으면 [요청]으로 안내만 한다.
   - docs/STATUS.md: 0단계 체크, 현재 단계를 1로, 처음 아이디어를 세션 로그에 기록.
2. **1-1 아이디어 브리프 시작**
   - docs/templates/idea-brief.md를 docs/product/idea-brief.md로 복사하고, 아이디어 원문을 그대로 적는다.
   - 아이디어가 비어 있으면 "어떤 걸 만들고 싶으세요? 한 줄이어도 됩니다"로 시작한다.
   - 아이디어 설명(과 첨부 문서)에서 브리프 8개 항목을 먼저 추출해 채운다. 설명에서 직접 읽히는 것만 채우고, 추측한 것은 `(가정)`으로 표시한다.
   - 비어 있거나 모호한 항목만 PROCESS.md 1-1 순서대로, 한 번에 1~4개씩 선택지와 추천안을 곁들여 질문한다. 이미 답이 있는 항목은 다시 묻지 않는다.
   - 빈 항목이 없으면 인터뷰를 생략하고, 채운 브리프 요약과 가정 목록을 보여주며 1-2(PRD)로 넘어가도 될지 [승인 요청]한다.
   - 답을 들을 때마다 브리프를 갱신한다. 추천안으로 정한 것은 `(가정)`으로 표시하고 STATUS.md 가정 표에도 적는다.
3. 응답은 항상 [질문] / [제안] / [승인 요청] / [요청] 중 하나로 끝낸다.
