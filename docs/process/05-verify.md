# 5단계: 검증

관행: 테스트 피라미드, CI

- **테스트 피라미드**: 단위 테스트 다수 > 통합 테스트 일부 > E2E/수동 소수.
- **CI**: PR마다 설치 → 린트 → 타입 체크 → 테스트 → 빌드. 실패한 PR은 병합하지 않는다. 모노레포에서는 변경된 패키지와 그 의존자만 테스트하는 것이 일반적이다 (Turborepo/Nx의 affected, 또는 경로 필터).
- **리뷰**: 작성한 세션과 다른 세션에서 `/review`를 돌리면 더 객관적이다.
- **통합 실행 확인**: 마일스톤 끝에 Claude가 앱을 처음부터 실행해 마일스톤의 사용자 시나리오 전체를 이어서 돌려 본다 (이슈별로는 통과했어도 함께 쓸 때 깨지는 것을 찾기 위함). 결과를 기록한다.
- **사람 확인**: Claude가 확인하지 못한 시나리오(실제 기기, 체감, 외부 계정)만 목록으로 만들어 **[요청]**하고, 결과를 기록한다.
- **요구사항 확인**: spec(PRD 5절)에서 이 마일스톤의 Must 요구사항마다 상태가 Done이고 닫힌 이슈와 대응 테스트(시나리오 ID 주석)가 있는지 표로 한 번 확인한다. 빠진 것은 이슈로 만들거나 [질문]한다.

**lite일 때**: 요구사항 확인은 브리프의 MVP 기능 목록 기준으로, F-ID마다 `mvp.md` 체크와 테스트가 있는지 본다.

**게이트 [승인 요청]**: 마일스톤의 모든 이슈가 DoD를 만족하고 사람 확인을 마쳤다. → [06-release.md](06-release.md)
