# 프로젝트 상태

Claude가 관리하는 진행 상태 문서. 세션이 시작될 때마다 CLAUDE.md를 통해 자동으로 로드된다.
사람이 직접 고쳐도 되며, 고친 내용이 우선한다.

## 현재

- 단계: 0 초기화
- 모드: 개발 (개발 / 유지보수 / 종료)
- 규모: — (lite / full, 1단계에서 정함)
- 마일스톤: —
- 진행 중 작업: —
- 다음 할 일: `/kickoff`로 아이디어 인터뷰 시작
- 최종 갱신: YYYY-MM-DD

## 사람 대기 항목

Claude가 사람에게 요청했고 아직 끝나지 않은 일. 완료되면 체크 후 다음 갱신 때 삭제한다.

- [ ] 

## 사람 확인 대기

실기기·체감 확인. 모아서 마일스톤 끝·릴리즈 전에 한 번에 요청한다.

| 출처 | 무엇을·어떻게 | 기대 결과 |
|---|---|---|
| | | |

## 단계 진행

- [ ] 0 초기화
- [ ] 1 아이디어·spec — 게이트: spec 승인 (`[제안]` 모두 확인)
- [ ] 2 설계 — 게이트: 설계 문서·ADR 승인 (lite는 1단계와 함께)
- [ ] 3 계획 — 게이트: 마일스톤·이슈 승인
- [ ] 4~5 구현·검증 — 게이트: 마일스톤 DoD, spec 대조 남은 할 일 0, 사람 확인
- [ ] 6 릴리즈 — 게이트: Must 기능 모두 Done, spec 커버리지 통과
- [ ] 7 회고

## 가정 (검증 필요)

spec 밖의 가정(일정, 환경, 외부 조건 등). 제품·동작에 관한 추천은 여기가 아니라 SPEC.md에 `[제안]`으로 둔다. 검증되면 결정 기록으로 옮긴다.

## 결정 기록

제품·범위에 관한 결정. 범위·동작이 바뀌는 결정은 같은 커밋에서 docs/SPEC.md를 먼저 고치고 여기엔 한 줄과 spec 링크만 둔다. 기술·구조 결정은 `docs/adr/`에 기록하고 여기엔 링크만 둔다.
